# Plan consolidado F6-F10 — Producción robusta

**Condición de inicio**: NO empezar hasta que las fases F4 (limpieza estructural) y F5
(calidad continua) estén terminadas, aprobadas y fusionadas a `main`.

**Dependencias**: F4, F5. **Alcance**: F6, F7, F8, F9, F10.

---

## F6 — Seguridad de secretos y dependencias

**Objetivo**: eliminar secretos hardcodeados, blindar credenciales y detectar vulnerabilidades.

1. Auditar secretos en el repo con grep.
2. Instalar y configurar gitleaks como pre-commit hook.
3. Centralizar secretos en `/etc/ura/*.env` con permisos 640.
4. Auditar dependencias con pip-audit.
5. Actualizar dependencias vulnerables y fijar versiones.
6. Añadir regla en AGENTS.md: prohibido commitear secretos.

**Gates**: gitleaks 0 hallazgos, pip-audit 0 vulnerabilidades críticas/altas, ruff OK.
**Cierre**: sin secretos activos, dependencias auditadas, hook funcionando.

---

## F7 — CI/CD con ramas protegidas

**Objetivo**: que cada PR pase automáticamente los gates antes de fusionarse.

1. Crear pipeline en GitHub Actions (`.github/workflows/ci.yml`) que ejecute ruff, mypy, pytest, gitleaks y pip-audit.
2. Proteger main: sin push directo, exigir 1 aprobación y CI verde.
3. Configurar CODEOWNERS para `core/`, `motor/` y `docs/`.
4. Activar DCO o firma de commits.
5. Crear plantilla de PR con TASK-ID, resumen, pruebas y evidencias.

**Gates**: CI verde en cada PR, revisión obligatoria aprobada, main protegida.
**Cierre**: PR de prueba pasa pipeline completo, main no acepta push directo.

---

## F8 — Monitoreo y alertas

**Objetivo**: saber en tiempo real si los servicios están sanos.

1. Activar Prometheus en ASUS.
2. Configurar exportadores: node_exporter, dcgm-exporter, exportador Qdrant.
3. Configurar Grafana con dashboards de sistema, API y colas de agentes.
4. Definir alertas críticas: RAM>90%, GPU>95%, servicio caído, disco>85%.
5. Conectar alertas a Telegram/Pushover usando `core/notifier.py`.

**Gates**: dashboards con datos reales, alerta simulada funciona.
**Cierre**: métricas recopiladas, alertas probadas.

---

## F9 — Backups automáticos y recuperación

**Objetivo**: garantizar restauración ante fallo grave.

1. Definir qué respaldar: código, `/etc/ura/`, secretos, Qdrant, logs críticos.
2. Crear `scripts/pro/backup_full.sh` con tar comprimido y timestamp.
3. Programar backup diario y semanal con cron/systemd.
4. Crear `scripts/pro/restore_backup.sh` y probar restauración en sandbox.
5. Registrar último backup y verificación en coordination.json.

**Gates**: backup generado, restauración íntegra, cron activo.
**Cierre**: backups automáticos y restauración probada.

---

## F10 — Observabilidad del flujo de agentes

**Objetivo**: monitorizar y controlar el trabajo de las IAs.

1. Confirmar `verify_protocol.py` como guardián.
2. Confirmar `dispatcher.py` como auto-asignador.
3. Crear panel de control que lea coordination.json y muestre tareas y agentes.
4. Registrar métricas: tiempo por tarea, rondas de revisión, tasa de aprobación.
5. Integrar despertador (TASK-009) para ejecutar dispatcher automáticamente.

**Gates**: guardián bloquea cierres sin revisión, dispatcher asigna bien, panel visible.
**Cierre**: flujo supervisado, sin tareas huérfanas.
